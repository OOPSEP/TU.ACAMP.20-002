# agent-jobs — คิวงานสำหรับ AI Agent

โฟลเดอร์นี้เก็บ "ใบสั่งงาน" ที่เขียนเสร็จแล้วและพร้อมส่งให้ AI Agent ลงมือทำ

## กติกาชื่อไฟล์

```
yyyy_MM_dd_NN-<JOB_NAME>.md                       ← งานที่ยังไม่ได้ทำ / กำลังทำ / ทำไม่จบ
yyyy_MM_dd_NN-<JOB_NAME>_ready_<agentname>.md     ← agent ทำเสร็จและรายงานผลครบแล้ว
```

ขึ้นต้นด้วยวันที่และลำดับเสมอ เพื่อให้ไฟล์ในโฟลเดอร์เรียงตามลำดับการสั่งงานโดยอัตโนมัติ

- `yyyy_MM_dd` — วันที่ออกใบสั่งงาน
- `NN` — ลำดับงานของวันนั้น 2 หลัก เริ่มที่ `01` (นับเฉพาะไฟล์ที่ขึ้นต้นด้วยวันที่เดียวกัน รวมไฟล์ที่ `_ready_` แล้วด้วย)
- `<JOB_NAME>` — ชื่องานแบบ UPPER_SNAKE_CASE เช่น `TASK_FIX_TOPICS_INCLUDE_BUG`, `SPEC_IMPORT_ACTIVITY_TOPIC_DIALOG_V2`
- `<agentname>` — ชื่อ agent ที่ทำงานนั้น ตัวพิมพ์เล็ก ไม่มีช่องว่าง เช่น `claude`, `gemini`, `codex`

## ขั้นตอนของ Agent

1. เลือกไฟล์ที่ **ยังไม่มี** `_ready_` ต่อท้าย
2. ทำงาน **เฉพาะขอบเขตในไฟล์ใบนั้นใบเดียว** — ห้ามแก้ไฟล์ที่เป็นของใบงานอื่นในโฟลเดอร์นี้ แม้จะเห็นว่าเกี่ยวข้องกันก็ตาม
   ถ้าเจอว่าจำเป็นต้องแตะงานอื่น ให้บันทึกไว้ในหัวข้อ `## Blocked` แล้วหยุด
3. ทำจนครบ **Definition of Done** ในหัวข้อสุดท้ายของใบงาน
4. **ติ๊ก checkbox ใน Definition of Done ให้ครบทุกข้อ** (`- [ ]` → `- [x]`) ตามผลจริง — ข้อไหนทำไม่ได้ให้คงเป็น `- [ ]`
5. **ต่อท้ายไฟล์ด้วยหัวข้อ `## Result`** ตามแม่แบบด้านล่าง — บังคับทุกใบ
6. เปลี่ยนชื่อไฟล์โดยต่อท้ายด้วย `_ready_<agentname>` ก่อนนามสกุล `.md`
7. บันทึกสรุปงานลง `Logs/Daily-Log-yyyy-MM-dd.md` ตามรูปแบบเดิมของโปรเจกต์

> **ห้าม rename เป็น `_ready_` ถ้ายังไม่มีบล็อก `## Result` ในไฟล์ และยังติ๊ก Definition of Done ไม่ครบ**
> ชื่อไฟล์ `_ready_` คือคำรับรองว่างานเสร็จ ต้องมีหลักฐานแนบในไฟล์เสมอ

## กรณีทำไม่จบ

คงชื่อไฟล์เดิมไว้ (ห้ามใส่ `_ready_`) แล้วต่อท้ายไฟล์ด้วย:

```markdown
## Blocked

- **Agent:** <agentname>
- **วันเวลา:** yyyy-MM-dd HH:mm
- **ทำถึงไหนแล้ว:** <ข้อ/หัวข้อที่ทำเสร็จ>
- **ติดอะไร:** <สาเหตุที่ไปต่อไม่ได้>
- **ไฟล์ที่แก้ไปแล้ว:** <รายการไฟล์ เพื่อให้คนหรือ agent รอบหน้าตามต่อได้>
```

## แม่แบบ `## Result` (บังคับ)

```markdown
## Result

- **Agent:** <agentname>
- **วันเวลาที่เสร็จ:** yyyy-MM-dd HH:mm

### ไฟล์ที่แก้ไข / สร้างใหม่ (ทั้งหมด ห้ามตกหล่น)

| ไฟล์ | แก้ไข / สร้างใหม่ | สรุปสิ่งที่ทำ |
|---|---|---|
| `path/to/file.cs` | แก้ไข | ... |

### ผลการตรวจรับ

- `dotnet build` — <ผลจริง เช่น 0 Error / 0 Warning>
- `dotnet test` — <ตัวเลขจริง เช่น 36 passed / 0 failed> และระบุชื่อเทสต์ใหม่ที่เพิ่ม
- เทสต์ที่ต้องแดงก่อนแก้ (ถ้าใบงานกำหนด) — <ยืนยันว่าเห็นแดงจริงก่อนแก้ หรือระบุว่าไม่ได้ทำ>
- ข้อที่ตรวจไม่ได้ / ไม่ได้ตรวจ — <ระบุให้ชัด ห้ามข้ามเงียบ ๆ>

### สิ่งที่เบี่ยงจากสเปก

<ระบุทุกจุดที่ทำไม่ตรงตามใบงาน พร้อมเหตุผล — ถ้าไม่มี ให้เขียนว่า "ไม่มี">
```
